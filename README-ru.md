## Что это

NetAssistant — сетевой отладочный инструмент для Windows, Linux и macOS. Он открывает клиентские
и серверные соединения, показывает каждое сообщение в журнале в виде чата и добавляет всё, что
нужно при отладке: движок правил автоответа, переменные сообщений, задачи отправки, стресс-тест и
встроенный тулбокс. Инструмент используют при работе с протоколами приложений, при отладке
встраиваемых устройств и при поиске IoT-устройств в локальной сети.

## Возможности

**Протоколы и роли**

| Протокол | Роли | Главное |
|---|---|---|
| TCP | клиент, сервер | декодеры: сырой, построчный, с префиксом длины и JSON (борьба со «склейкой» пакетов), IPv4/IPv6, локальная привязка адреса |
| UDP | клиент, сервер | broadcast-поиск: ответы с неожиданных адресов подсвечиваются, ручное добавление клиента в серверном режиме |
| MQTT 3.1.1 / 5.0 | клиент | QoS 0/1/2, clean session, keepalive, will-сообщение, TLS (системные корни / свой CA / взаимная аутентификация), подписки во время сессии с восстановлением после reconnect |
| UDP-сессия | клиент | защищённый протокол сессии: взаимное рукопожатие, AES-256-GCM, push-кадры от устройства (см. ниже) |

**Тулбокс** — text ⇄ Hex, шесть контрольных сумм (XOR, Sum8, LRC, CRC16-Modbus,
CRC16-CCITT-FALSE, CRC32), хеши (MD5 … SHA-512, bcrypt / Argon2id / PBKDF2), timestamp ⇄ дата,
JSON beautify/minify, Base64 и URL-кодирование.

**Журнал сообщений** — чат-подобный журнал с копированием, избранным, поиском и инструментами
выделения; текстовый и hex-виды; форматирование JSON; экспорт в TXT/JSON/CSV; по желанию —
запись в файл в реальном времени; ограничение «оставить последние N» для контроля памяти.

**Автоматизация и тесты** — движок правил автоответа (byte-level условия, JSON-пути, CIDR по
адресу источника, вложенные all/any/not, срабатывает первое правило, проверка прямо в редакторе);
переменные сообщений (`${seq}`, `${timestamp}`, `${uuid}`, `${random:min:max}`, `${rx.*}`,
`${rx.json:path}`, контрольные суммы, `${= expression }`); построчные задачи отправки и таймерные
heartbeat-задачи; суффикс LF/CRLF; стресс-тест TCP/UDP с QPS, перцентилями задержек и CSV-отчётом.

**Интерфейс** — светлая и тёмная тема по системной, несколько вкладок соединений, интерфейс на
китайском и английском, hex-редактор, источник данных из файла (UTF-8/GBK/ANSI), горячие клавиши.

## Протокол UDP-сессии

Отдельный тип соединения для устройств, говорящих по защищённому протоколу сессии
household-IoT. Реализована только роль клиента; серверной роли нет.

**Рукопожатие.** Четыре кадра, все открытым текстом:

1. Клиент → `HELLO`: случайный nonce.
2. Устройство → `CHALLENGE`: свой nonce устройства плюс доказательство.
3. Клиент → `RESPONSE`: доказательство клиента.
4. Устройство → `SESSION_OK`: сессия открыта — либо `SESSION_ERR` с кодом причины.

Каждое доказательство — HMAC-SHA256 над общим секретом и обоими nonce, с байтом-контекстом,
разным для каждого направления, поэтому доказательство нельзя переслать обратно как ответ другой
стороны. Клиент проверяет доказательство устройства до того, как отвечает; неверное
доказательство прерывает попытку. По таймауту рукопожатия `HELLO` повторяется с тем же nonce.

**Ключ сессии.** HKDF-SHA256 выводит 256-битный ключ из общего секрета (входной ключевой
материал) и обоих nonce (соль), с фиксированной протокольной меткой в качестве info. Обе стороны
получают одинаковый ключ, не передавая его по сети.

**Шифрованный трафик.** После рукопожатия каждый кадр закрывается AES-256-GCM: уникальный nonce
на кадр (в него входят session id, направление и номер кадра), заголовок кадра идёт как
дополнительные аутентифицированные данные, плюс 16-байтный тег. Конфиденциальность и
целостность даёт одна и та же операция — повреждённый кадр отбрасывается, сессия остаётся живой.

**Порядок и защита от повторов.** Номера кадров растут строго в каждом направлении и не
переиспользуются; получатель хранит следующий ожидаемый номер, поэтому пересланный или
пропущенный кадр отвергается. Для зашифрованных кадров дополнительно проверяется окно
300 секунд по метке времени. Само рукопожатие по времени не проверяется: часы компьютера —
ненадёжный источник времени.

**Типы кадров.** `DATA` несёт пользовательские данные и команды, `PUSH` — снимки состояния и
события от устройства, `CLOSE` завершает сессию с причиной (отключение пользователем, таймаут,
ротация секрета, ошибка).

**Что видно в журнале.** Только расшифрованные данные — шифротекст и теги в журнал не пишутся.
Стадии протокола показываются отдельными строками (socket, decoder, handshake, session, sender,
push, reply) с именами полей протокола, поэтому сессию можно читать по кадрам.

**Правила автоответа не применяются.** К трафику сессии правила автоответа не применяются:
правило по открытому тексту обошло бы аутентификацию GCM.

**Секреты.** Общий секрет не попадает ни в логи, ни в подсказки, ни в тексты ошибок, ни в
экспортированные журналы.

## Установка

**Windows** — `winget install SunJary.NetAssistant` (обновление: `winget upgrade
SunJary.NetAssistant`), либо установщик или portable-архив со
[страницы релизов](https://github.com/sunjary/netassistant/releases).

**Linux** — скачать `.deb` и выполнить `sudo apt install ./netassistant-*.deb`, либо распаковать
tar.gz и запустить `./netassistant`.

**macOS** — скачать `.dmg`, перетащить NetAssistant в Applications, при первом запуске открыть
правой кнопкой («Открыть») — так срабатывает Gatekeeper.

Требования: Windows 10 1709 или новее (включая Windows 11), Linux с GTK3, macOS 10.15 или новее.

**Сборка из исходников**

```bash
git clone https://github.com/sunjary/netassistant.git
cd netassistant
cargo build --release
```
